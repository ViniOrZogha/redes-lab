## Antes de começar

<walkthrough-tutorial-duration duration="60"></walkthrough-tutorial-duration>

Você vai montar duas redes separadas, colocar máquinas em cada uma e provar
duas coisas opostas: que dentro de um segmento tudo se enxerga, e que entre
segmentos **nada** passa.

**Vale 0,8** · **Prazo: semana 6** · vocês entregam em grupo.

O que precisa chegar até o professor:
1. o link do repositório do grupo, com o `docker-compose.yml` completo;
2. o arquivo `evidencias/verificacao.txt` gerado por vocês;
3. o **plano de endereçamento** escrito no `README.md` do repositório: quais
   sub-redes vocês usaram, quantos endereços cabem em cada uma, e qual endereço
   foi para cada máquina.

Comece construindo a imagem do laboratório — uma vez por sessão:

```bash
make base
```

## Suba o que já existe

```bash
make up E=1 && make verificar E=1
```

Vai ficar **vermelho**, e isso é o esperado. O laboratório começa incompleto de
propósito: o roteiro de verificação é o enunciado de verdade, e o trabalho de
vocês é levá-lo ao verde.

Leia com atenção o que ele reclamou. Ele não diz só "falhou": diz o que
observou em cada ponto.

## Sua tarefa

Abra o arquivo da topologia:

<walkthrough-editor-open-file filePath="e1-segmentos/docker-compose.yml">
abrir o docker-compose.yml
</walkthrough-editor-open-file>

O segmento A está pronto: dois hosts e um servidor HTTP. O segmento B está
declarado, mas **vazio**. Coloquem lá dois hosts, chamados `e1-host-b1` e
`e1-host-b2`, com endereços da sub-rede `10.0.20.0/24`.

Copiem o padrão de `host-a1`. Duas perguntas que vocês precisam saber responder
na apresentação:

* por que o endereço `10.0.20.0` e o `10.0.20.255` não servem para uma máquina?
* quantos hosts cabem, ao todo, numa `/24`?

Antes de escrever, passem pelo simulador de sub-redes da disciplina. Ele resolve
a conta; aqui vocês vão **executar** o resultado dela.

## Prove

```bash
make up E=1 && make verificar E=1
```

Cinco provas precisam ficar verdes, e elas se sustentam em pares:

* dentro de A e dentro de B o ping **funciona**;
* de A para B ele **falha** — e falha dizendo `Network is unreachable`.

Repare que só a segunda metade não provaria nada: com tudo desligado, o ping
também falharia. É por isso que o roteiro exige as duas.

## Gere a evidência e entregue

```bash
make evidencias E=1
```

Depois:

```bash
git add -A && git commit -m "Entrega 1" && git push
```

Volte à página da disciplina, cole o link do repositório no formulário de
entrega e envie. Cada integrante recebe uma cópia por e-mail — guardem, é o
comprovante.

## Como é corrigido

| O quê | Pontos |
|---|---|
| `make verificar E=1` verde numa Cloud Shell limpa | 0,4 |
| Plano de endereçamento no README, com as contas | 0,2 |
| Explicação escrita de **por que** A não alcança B | 0,2 |
